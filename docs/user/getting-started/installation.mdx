Vespertine is available on the following distributions. Choose your platform below, or use the manual installation method on another Linux distribution.

- [Arch Linux](#arch)
- [NixOS](/vespertine/getting-started/nixos/)
- [Fedora](#fedora)
- [openSUSE](#opensuse)
- [Gentoo](#gentoo)
- [GNU Guix](#guix)
- [Debian](#debian) (including Ubuntu)
- [Chimera Linux](#chimera)
- [Void Linux](#void)
- [Solus](#solus)
- [Alpine Edge](#alpine)

You can also [install manually](#manual-install) on any other Linux distribution.

:::note[Package ownership]
The Vespertine team maintains the **manual installation method**. Official distribution packages are maintained through their distributions' own packaging processes; other repositories listed here are community-maintained. Review a third-party repository before installing from it.
:::

<details>
  <summary>Already using Vespertine Shell v4?</summary>

  Vespertine v5 is a fresh install, not an automatic upgrade from the Quickshell-based v4 implementation. Its package and configuration files are separate, so both versions can be installed at the same time on most distributions, but v4 settings are not migrated.

  Only your **compositor keybinds** need attention. Update any bindings that launch the Vespertine launcher, panels, settings UI, or other commands when switching between versions.
</details>

## Arch Linux {#arch}

Vespertine is available in the \[extra] repository.

```bash
sudo pacman -S vespertine
```

## Fedora {#fedora}

Vespertine is available from the default repos for Fedora 44 and up.

```bash
sudo dnf install vespertine
```

##### An alternate version using git snapshots is available from the [LionHeartP Copr](https://copr.fedorainfracloud.org/coprs/lionheartp/Hyprland/) repository.

**Step 1**: Enable the repository

```bash
sudo dnf copr enable lionheartp/Hyprland 
```

**Step 2**: Install vespertine-git

```bash
sudo dnf install vespertine-git
```

## Gentoo {#gentoo}

Vespertine is available in the [GURU](https://wiki.gentoo.org/wiki/Project\:GURU) overlay.

**Step 1**: Enable and sync the overlay as read in [Project:GURU/Information_for_End_Users](https://wiki.gentoo.org/wiki/Project\:GURU/Information_for_End_Users).

**Step 2**: [Unmask](https://wiki.gentoo.org/wiki/Live_ebuilds#Unmasking_live_ebuilds) the `gui-apps/vespertine` package:

```
gui-apps/vespertine ~amd64
```

**Step 3**: Emerge the package:

```bash
emerge --ask gui-apps/vespertine
```

## GNU Guix {#guix}

Vespertine is available in the main Guix repository as the package `vespertine-shell`. Simply add `(gnu packages window-management)` to your list of imported modules, then add `vespertine-shell` to your list of packages.

Due to the fast pace of development on Vespertine, the main Guix channel is likely to lag behind in version. If you don't wish to wait for it to update then you have two alternative channels. Do note that with both options you will be compiling the package yourself, because only the main Guix channel provides substitutes for it.

<Tabs>
  <TabItem label="Vespertine channel">
    The Git repository of Vespertine is also available as a [Guix channel](https://guix.gnu.org/manual/devel/en/html_node/Channels.html).  It provides a `(vespertine)` module with the `vespertine-git` package.

    Do note that since this is a git package, there might be times (though rare) where it fails to compile when either dependencies or something about the build process changes. If that happens you might want to [pin the channel](https://guix.gnu.org/manual/devel/en/html_node/Replicating-Guix.html) to an older working commit by adding `(commit "[full commit hash]")` to the channel definition.

    ```scheme
    (channel
      (name 'vespertine)
      (url "https://github.com/vespertine-dev/vespertine")
      (branch "main"))
    ```

    Whenver you run `guix pull` you will get the latest commit of vespertine, which will start compiling and be available for use when you reconfigure your system or home environment, whichever you added the `vespertine-shell` package to. You can use `guix pull --select=vespertine` if you wish to update only vespertine without needing to pull your other channels.
  </TabItem>

  <TabItem label="Midnight channel">
    The third-party [`midnight`](https://codeberg.org/stampede/midnight) guix channel provides the `vespertine` package under the module `(midnight packages vespertine)`. It provides up-to-date stable releases of vespertine for those who prefer that over a git package.

    ```scheme
    (channel
      (name 'midnight)
      (url "https://codeberg.org/stampede/midnight.git")
      (branch "main")
      (introduction
        (make-channel-introduction
          "d97d1568954cfcbf543c9fcdfd5771e2b730ae19"
          (openpgp-fingerprint
            "640A 2C3C E948 22D3 394B 40C3 CAFA EECA 00FF 9B1E"))))
    ```
  </TabItem>
</Tabs>

## Debian {#debian}

Vespertine provides an APT repository for Debian-based distributions.

**Step 1**: Install the repository signing key

```bash
wget https://pkg.vespertine.dev/deb/nickh-archive-keyring.deb && sudo dpkg -i nickh-archive-keyring.deb
```

**Step 2**: Add the repository

<Tabs>
  <TabItem label="Debian Trixie">
    ```bash
    sudo wget -O /etc/apt/sources.list.d/vespertine-trixie.sources https://pkg.vespertine.dev/deb/vespertine-trixie.sources
    ```
  </TabItem>

  <TabItem label="Debian Sid">
    ```bash
    sudo wget -O /etc/apt/sources.list.d/vespertine-unstable.sources https://pkg.vespertine.dev/deb/vespertine-unstable.sources
    ```
  </TabItem>

  <TabItem label="Ubuntu 26.04">
    ```bash
    sudo wget -O /etc/apt/sources.list.d/vespertine-resolute.sources https://pkg.vespertine.dev/deb/vespertine-resolute.sources
    ```
  </TabItem>

  <TabItem label="Ubuntu 26.10">
    ```bash
    sudo wget -O /etc/apt/sources.list.d/vespertine-stonking.sources https://pkg.vespertine.dev/deb/vespertine-stonking.sources
    ```
  </TabItem>
</Tabs>

**Step 3**: Install vespertine

```bash
sudo apt update
sudo apt install vespertine
```

You can also install the `vespertine-greeter`, `umbriel`, and `xdg-desktop-portal-umbriel` packages.

:::note
The APT repository provides `amd64` and `arm64` packages only.
:::

***Configuring `vespertine-greeter`***

<ol>
  <li>
    If already using `greetd`, no configuration is required. Just restart greetd with:

    ```bash
    sudo systemctl restart greetd
    ```
  </li>

  <li>
    If not currently using `greetd`

    First stop and disable your current display manager. Eg:

    ```bash
    sudo systemctl disable --now gdm3
    ```

    Then enable and start `greetd`. Eg:

    ```bash
    sudo systemctl enable --now greetd
    ```
  </li>
</ol>

## Chimera Linux {#chimera}

Vespertine is available in Chimera's `user` repository.

Run the following commands as root.

**Step 1**: Enable the `user` repository if it isn't already:

```sh
doas apk add chimera-repo-user
```

**Step 2**: Refresh the package indexes and install Vespertine:

```sh
doas apk update
doas apk add vespertine
```

## [Alpine Edge](#alpine)

Vespertine is provided by third-party repository [`UniversalRepository`](https://universalrepo.pages.dev). This third party repository currently supports Alpine Edge only.

**Step 1**: Import the key

```sh
curl -fLo universalrepository.rsa.pub https://downloads.sourceforge.net/project/universalrepository/alpine/universalrepository.rsa.pub
doas install -m 644 universalrepository.rsa.pub /etc/apk/keys/
rm universalrepository.rsa.pub
```

**Step 2**: Add the repository and sync

```sh
echo 'https://downloads.sourceforge.net/project/universalrepository/alpine/community' | doas tee -a /etc/apk/repositories
doas apk update
```

**Step 3**: Install Vespertine

```sh
doas apk add vespertine
```

## Manual Installation {#manual-install}

:::caution[Not Recommended]
Manual installation has **no easy upgrade path**. You will need to manually download and replace files for each update. We strongly recommend using a package manager ([Arch](#arch), [Fedora](#fedora)) whenever possible.
:::

If you prefer to install Vespertine locally or want more control over the installation process, you can install it manually to your user configuration directory. This method works on any Linux distribution.

Vendored dependencies, with no system package needed: `Wuffs`, `Luau`, `fzy`, and Material Color Utilities.

System packages required beyond the Wayland/GL stack: `libwebp` handles WebP decoding and thumbnail encoding. Wuffs handles the other supported raster image formats.

HEIC, HEIF, and AVIF images are optional and need no build-time package: Vespertine loads `libheif.so.1` at runtime the first time it meets one. Install `libheif` with its AV1 (dav1d or aom) and HEVC (libde265) decoder plugins to use them; on Fedora the HEVC plugin comes from RPM Fusion's `libheif-freeworld`.

Polkit agent support requires development files that provide the `polkit-agent-1` and `polkit-gobject-1` pkg-config modules. Some distros ship these in the runtime `polkit` package, while split-package distros use names such as `polkit-devel`, `polkit-dev`, or `libpolkit-agent-1-dev` / `libpolkit-gobject-1-dev`.

**Optional:** installing `jemalloc` (Fedora: `jemalloc-devel`, Arch: `jemalloc`, Debian/Ubuntu: `libjemalloc-dev`, Void: `jemalloc`) reduces memory fragmentation in long-running sessions. On glibc systems it is used automatically when detected. Use Meson's `-Djemalloc=enabled` or `-Djemalloc=disabled` option to require or disable it explicitly.

Sanitizer runtime packages are only needed for ASan/UBSan builds configured with `just configure asan`.

**Step 2**: Prepare directory

```bash
git clone https://github.com/vespertine-dev/vespertine --branch main
cd vespertine
```

**Step 3**: Building and installing Vespertine

Requires [just](https://github.com/casey/just) and [meson](https://mesonbuild.com/).

<Tabs>
  <TabItem label="Release Mode">
    ```bash
    # Optimized release build in build-release/
    just configure release
    just build release

    # Install the selected build mode. This does not build or reconfigure.
    sudo just install release
    ```

    Pass a prefix to `configure` to install somewhere other than `/usr/local`:

    ```bash
    just configure release "$HOME/.local"
    just build release
    just install release
    ```

    To remove files installed from a build directory, run `just uninstall release`.
  </TabItem>

  <TabItem label="Debug Mode">
    ```bash
    # Debug build in build-debug/ for local development and troubleshooting.
    just configure
    just build

    # Test your local debug build with 
    just run
    ```
  </TabItem>
</Tabs>

Meson installs the binary, the lock screen PAM helper and shipped assets using the normal prefix layout:

```text
/usr/local/bin/vespertine
/usr/local/libexec/vespertine/vespertine-pam-helper
/usr/local/share/vespertine/assets/...
```

Vespertine needs the shipped `assets/` tree at runtime, and the lock screen needs `vespertine-pam-helper`. Copying only the `vespertine` binary is not enough.

Portable bundle layouts are also supported:

```text
bundle/
  vespertine
  vespertine-pam-helper
  assets/
```

```text
bundle/
  bin/vespertine
  bin/vespertine-pam-helper
  share/vespertine/assets/
```

See [PACKAGING.md](https://github.com/vespertine-dev/vespertine/blob/main/PACKAGING.md#runtime-asset-lookup) for the full runtime asset lookup order.

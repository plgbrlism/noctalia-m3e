:::tip[Method]
Use compositor autostart as the primary method.
:::

### Autostart by your Wayland compositor

This is the recommended method for launching vespertine, as it integrates with your window manager.

For the *Umbriel* compositor, add `vespertine` to the existing `autostart` array under `[general]` in `~/.config/umbriel/config.toml`. Preserve any commands already in the array:

```toml
[general]
autostart = ["vespertine"]
```

For the *Niri* compositor, add the following line to the end of your configuration file, typically located at `~/.config/niri/config.kdl`

```ini
spawn-at-startup "vespertine"
```

For the *Hyprland* compositor, append this to your existing `hyprland.start` event hook in your Lua configuration file, typically located at `~/.config/hypr/hyprland.lua`

```lua
hl.on("hyprland.start", function()
  hl.exec_cmd("vespertine")
end)
```

If your compositor expects startup commands to return after the shell has initialized, run Vespertine in daemon mode:

```bash
vespertine --daemon
```

Daemon mode returns after the shell has initialized. The optional polkit authentication agent starts asynchronously after the UI is up.

---

### Manual Launch for Debugging

The most direct way to run Vespertine for testing or debugging. Open a terminal and execute:

```bash
vespertine
```

### Logs

Vespertine writes its main log to `$XDG_CACHE_HOME/vespertine/vespertine.log`. If `XDG_CACHE_HOME` is unset, the fallback path is `~/.cache/vespertine/vespertine.log`. The previous file is retained as `vespertine.log.1` when the current log reaches 1 MiB.

:::caution
To make Vespertine's wifi, bluetooth, power-profile, and battery feature available, please ensure the following NixOS options are enabled:

- `networking.networkmanager.enable`
- `hardware.bluetooth.enable`
- `services.power-profiles-daemon.enable` or `services.tuned.enable`
- `services.upower.enable`
:::

## Installation

A Vespertine package is available on [nixpkgs unstable](https://search.nixos.org/packages?channel=unstable\&show=vespertine).

If you'd prefer the latest git version or would like to use one of the modules, you can [add the input](#add-input) using your preferred input-pinning method and optionally use the [binary cache](#binary-cache) to avoid compiling locally.

### Adding the input {#add-input}

<Tabs>
  <TabItem label="flakes">
    Add Vespertine to your flake inputs:

    ```nix
    # flake.nix
    {
      inputs = {
        vespertine = {
          url = "github:vespertine-dev/vespertine";
          inputs.nixpkgs.follows = "nixpkgs"; # this line is optional, prevents downloading two versions of nixpkgs but disables cache
        };
      };
    }
    ```

    :::note
    For flakes/tack instructions, we assume you are passing in `inputs` through `specialArgs` or equivalent.
    :::
  </TabItem>

  <TabItem label="tack">
    Add Vespertine to your tack inputs:

    ```
    tack add vespertine github:vespertine-dev/vespertine
    ```

    If you want to use the cache, make sure to disable any sort of following for Vespertine's nixpkgs input.

    :::note
    For flakes/tack instructions, we assume you are passing in `inputs` through `specialArgs` or equivalent.
    :::
  </TabItem>

  <TabItem label="npins">
    Add Vespertine to your npins sources:

    ```
    npins add github vespertine-dev vespertine --branch main
    ```

    ```nix
    # configuration.nix
    { pkgs, ... }:
    let
      vespertine = import (import ./npins).vespertine {
        inherit pkgs; # this line is optional, prevents downloading two versions of nixpkgs but disables cache
      };
    in
      # see installation below
    ```
  </TabItem>

  <TabItem label="tarball">
    Add Vespertine directly using `builtins.fetchTarball`. With pinning:

    ```nix
    # configuration.nix
    { pkgs, ... }:
    let
      vespertine-src = let
        commit = ""; # replace this with an actual commit id or tag
      in
        fetchTarball {
          url = "https://github.com/vespertine-dev/vespertine/archive/${commit}.tar.gz";
          sha256 = ""; # replace this with hash from nix build output, or by using `nix-prefetch-url --unpack`
        };
      
      vespertine = import vespertine-src {
        inherit pkgs; # this line is optional, prevents downloading two versions of nixpkgs but disables cache
      };
    in
      # see installation below
    ```

    Without pinning (not recommended):

    ```nix
    # configuration.nix
    { pkgs, ... }:
    let
      vespertine-src = fetchTarball "https://github.com/vespertine-dev/vespertine/archive/main.tar.gz";

      vespertine = import vespertine-src {
        inherit pkgs; # this line is optional, prevents downloading two versions of nixpkgs but disables cache
      };
    in
      # see installation below
    ```
  </TabItem>
</Tabs>

### Installing the Package {#install-package}

Note that both the Home Manager and Hjem modules install the package for you, so you can omit this step.

<Tabs>
  Add the package to your system packages or equivalent:

  <TabItem label="flakes/tack">
    ```nix
    # configuration.nix
    { inputs, pkgs, ... }:
    {
      environment.systemPackages = [
        inputs.vespertine.packages.${pkgs.stdenv.hostPlatform.system}.default
      ];
    }
    ```
  </TabItem>

  <TabItem label="npins/tarball">
    ```nix
    # configuration.nix
    let
      # see adding the input above
    in {
      environment.systemPackages = [
        vespertine.package
      ];
    }
    ```
  </TabItem>
</Tabs>

### Home Manager Module {#home-manager}

The Home Manager module allows you to configure Vespertine's settings [(that you would otherwise put in `~/.config/vespertine/`)](/vespertine/configuration/) using nix instead of toml, or allows you to link an existing toml file. It is optional.

<Tabs>
  <TabItem label="flakes/tack">
    ```nix
    { inputs, ... }:
    {
      home-manager.users.drfoobar = {
        imports = [
          inputs.vespertine.homeModules.default
        ];

        programs.vespertine = {
          enable = true;

          settings = { # This may also be a string or path to a .toml file.
            theme = {
              mode = "dark";
              source = "builtin";
              builtin = "Catppuccin";
            };

            wallpaper = {
              enabled = true;
              default.path = "/path/to/wallpapers/wallpaper.png";
            };
          };
        };
      };
    }
    ```
  </TabItem>

  <TabItem label="npins/tarball">
    ```nix
    let
      # see adding the input above
    in {
      home-manager.users.drfoobar = {
        imports = [
          vespertine.homeModule
        ];

        programs.vespertine = {
          enable = true;

          settings = { # This may also be a string or path to a .toml file.
            theme = {
              mode = "dark";
              source = "builtin";
              builtin = "Catppuccin";
            };

            wallpaper = {
              enabled = true;
              default.path = "/path/to/wallpapers/wallpaper.png";
            };
          };
        };
      };
    }
    ```
  </TabItem>
</Tabs>

:::note
Home Manager settings provide Vespertine's declarative configuration. Wallpaper selections made through the UI or IPC are saved in `~/.local/state/vespertine/settings.toml` and take priority over `wallpaper.default.path`. Completing setup without choosing a wallpaper does not save one, so the declared wallpaper applies.

To restore the declared wallpaper after a runtime selection, stop Vespertine and remove the saved `path` entries under `[wallpaper.default]`, `[wallpaper.last]`, and any relevant `[wallpaper.monitors."<connector>"]` tables from `settings.toml`, then restart Vespertine. `wallpaper.last.path` remembers the last selection for wallpaper-derived palettes and greeter sync, so clearing it also restores those to the configured wallpaper. Preserve unrelated settings. The same steps clear the bundled wallpaper path that older versions saved when setup completed.
:::

### Nix-managed plugins {#plugins}

Pin a plugin repository alongside Vespertine. The official plugin repository contains plugin sources without a `flake.nix`, so set `flake = false`. Nix still records its revision and content hash in `flake.lock`:

```nix
inputs.vespertine-plugins = {
  url = "github:vespertine-dev/official-plugins";
  flake = false;
};
```

Use it as a read-only `path` source in the Home Manager module. Plugin versions then follow your `flake.lock`, including updates and rollbacks:

```nix
{ inputs, pkgs, ... }:
{
  imports = [ inputs.vespertine.homeModules.default ];

  programs.vespertine = {
    enable = true;
    extraPackages = [ pkgs.gpu-screen-recorder pkgs.slurp ];

    settings = {
      plugins = {
        enabled = [ "vespertine/screen_recorder" ];
        source = [
          {
            name = "official";
            kind = "path";
            location = "${inputs.vespertine-plugins}";
            enabled = true;
          }
        ];
      };
      plugin_settings."vespertine/screen_recorder" = {
        frame_rate = 30;
        show_cursor = false;
      };
    };
  };
}
```

An explicit `plugins.source` list replaces the default sources. Vespertine reads path sources directly and never updates their contents. Choose plugin revisions compatible with your Vespertine version.

The Home Manager module's `programs.vespertine.extraPackages` option adds executables to Vespertine's `PATH`, including when launched by systemd or through the desktop launcher. It wraps the selected `programs.vespertine.package` without rebuilding Vespertine and requires that package to be non-null. List the packages required by your plugins; dependencies are not installed automatically from plugin manifests.

Plugin settings use the keys declared in each plugin's `plugin.toml`. Runtime changes in Settings take precedence over the declarative defaults; see [Plugin settings](/vespertine/plugins/#plugin-settings).

### NixOS Module {#nixos-module}

The NixOS module installs the package system-wide and can enable some recommended services.

<Tabs>
  <TabItem label="flakes/tack">
    ```nix
    { inputs, ... }:
    {
      imports = [
        inputs.vespertine.nixosModules.default
      ];

      programs.vespertine = {
        enable = true;

        # Enables NetworkManager, Bluetooth, UPower, and a power profile service.
        recommendedServices.enable = true;
      };
    }
    ```
  </TabItem>

  <TabItem label="npins/tarball">
    ```nix
    let
      # see adding the input above
    in {
      imports = [
        vespertine.nixosModule
      ];
      
      programs.vespertine = {
        enable = true;
      
        # Enables NetworkManager, Bluetooth, UPower, and a power profile service.
        recommendedServices.enable = true;
      };
    }
    ```
  </TabItem>
</Tabs>

### Systemd Service {#systemd}

Each of the above modules includes a systemd user service for Vespertine, which can be enabled by setting `programs.vespertine.systemd.enable = true`.

:::note
When using the service, it is recommended to enable `launch_apps_as_systemd_services`, otherwise any apps launched by Vespertine will be terminated when the service restarts.
:::

### Binary Cache {#binary-cache}

Pre-built binaries are available on [Cachix](https://app.cachix.org/cache/vespertine), so you can skip compiling locally.

You can configure the substituter either in your NixOS config, flake, or `/etc/nix/nix.conf`:

:::caution
To use the binary cache, you have to omit `inputs.nixpkgs.follows` from the Vespertine input with flakes/tack or avoid `inherit pkgs;` with npins/tarball.
:::

You can add the cache either to your flake, nixos configuration, or `/etc/nix/nix.conf`.

<Tabs>
  <TabItem label="configuration.nix">
    ```nix
    nix.settings = {
      extra-substituters = [ "https://vespertine.cachix.org" ];
      extra-trusted-public-keys = [ "vespertine.cachix.org-1:pCOR47nnMEo5thcxNDtzWpOxNFQsBRglJzxWPp3dkU4=" ];
    };
    ```
  </TabItem>

  <TabItem label="flake.nix">
    ```nix
    nixConfig = {
      extra-substituters = [ "https://vespertine.cachix.org" ];
      extra-trusted-public-keys = [ "vespertine.cachix.org-1:pCOR47nnMEo5thcxNDtzWpOxNFQsBRglJzxWPp3dkU4=" ];
    };
    ```
  </TabItem>

  <TabItem label="nix.conf">
    ```properties
    extra-substituters = https://vespertine.cachix.org
    extra-trusted-public-keys = vespertine.cachix.org-1:pCOR47nnMEo5thcxNDtzWpOxNFQsBRglJzxWPp3dkU4=
    ```
  </TabItem>
</Tabs>

Overriding any of Vespertine's inputs (e.g. via `inputs.nixpkgs.follows` with flakes) changes the derivation hash, causing cache misses.

Additionally, tracking `main` directly may pull in a commit that hasn't been cached yet by CI.

To avoid this, the [`cachix`](https://github.com/vespertine-dev/vespertine/tree/cachix) branch always points to the latest cached commit. Pinning to this branch guarantees you always track the latest commit that has already been cached:

<Tabs>
  <TabItem label="flakes">
    ```nix
    vespertine.url = "github:vespertine-dev/vespertine/cachix";
    ```
  </TabItem>

  <TabItem label="tack">
    ```
    tack add vespertine github:vespertine-dev/vespertine/cachix
    ```
  </TabItem>

  <TabItem label="npins">
    ```
    npins add github vespertine-dev vespertine --branch cachix
    ```
  </TabItem>

  <TabItem label="tarball">
    Make sure not to update your tarball to a commit earlier than the latest commit on the cachix branch.
  </TabItem>
</Tabs>
